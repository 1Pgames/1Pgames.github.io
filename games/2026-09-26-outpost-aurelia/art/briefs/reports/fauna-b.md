## Pipeline as actually run (read this before re-running anything)

- **The order of input images is wrong in generation-plan §0.5.** The middleware adds style anchors AFTER the explicit `input`: `merged.input = [...existing, ...anchors]` in `extensions/sprite-generate.ts:860`. So a call with an explicit input sends that input as **Image 1** and `vision-1.png` as **Image 2**. Every fauna-b prompt says it that way. Walk sheets used `fauna-skitter-walk/sprite-sheet.png` as Image 1, which pins the family's chitin, rendering and outline. Siblings used their own accepted walk sheet as Image 1, which pins identity. `vision-1` was Image 2 (palette and lighting) in both cases. Each call used 2 of the 3 input slots.
- **The chroma guard causes false strict failures on pink-key raws.** It was filed through `xd://report_issue`. The guard keeps whole pink background regions opaque. In strict QC that shows up as `source-edge-touch` and as inflated `profile-body-scale-drift`, on raws that are clean. Measured on the same raw, first with the guard and then without it:
  - titan-walk a2: 4× source-edge-touch → pass.
  - bloat-attack: drift 0.2864 plus 4× edge-touch → pass.
  - matron-attack: drift 0.1743 plus edge-touch → pass.

  So before calling any failed marker export a generation defect, I reprocessed its raw without the guard. The params were the same effective marker params `rekey.py` uses (threshold 150, feather 55, edgeThreshold 170, preserve, feet, fit 0.86, largest), plus the bound `--scale-profile`. The helper is `_scratch/proc.sh`. Exports that passed through the marker were re-keyed with `art/tools/rekey.py` as §0.2 says, and their marker metadata is kept as `sprite-metadata.marker.json`. Exports that failed at the marker have no `.marker.json`. Their provenance is `source.provider = xai-oauth` in the metadata, plus the prompts logged below.
- **Cell size.** Trash fauna use 256 cells. The alphas (matron 176 px, titan 256 px on screen) use **512 cells**, so the titan is shown at or below source resolution rather than upscaled from about 95 px.
- **Facing.** Every sheet of every species faces RIGHT, like the skitter. Matron walk a1 and a2 faced left and were rejected partly for that.
- **Transient network error.** A batch of 6 parallel calls all failed with `urlopen error [Errno 49] Can't assign requested address`. The very next single call succeeded, and batches of 2-3 always worked. The limit was the client's parallel connections, not the provider or the prompts. No image was generated by the failed batch, so it was not counted as attempts.

## CRITERIA

- **Rescoped: "a failed marker export = a generation defect."** With `styleProfile` bound on pink-key raws, strict failures for `source-edge-touch` and for large profile drift can be processing artefacts caused by the chroma guard. They were measured on 3 raws that passed guard-free. Scope: actor sheets with an xai pink key. Rule: reprocess guard-free before counting a regeneration.
- **Scoped: size drift on siblings.** It is a measured xai size prior across 5 of 5 species (−7 to −15%), not a prompt defect. The "same exact size as Image 1" wording did not move it (howler 0.138 → 0.097, matron brood 0.132 → 0.143). I did not use `postureChange` to hide it. It was used only on titan-stomp, where the body really rears and crouches.
- **No post-review pixel transforms were reviewed through** in this group. The runtime transforms still pending are the oxblood outline bake (`core/outline.ts`, fauna `#3a1712` 3/4/5 px) and any night grade. The integrator should review the fauna sheets with the outline and the night grade applied.
